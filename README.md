# Review / Free Solo Lab

Локальное приложение для ревью GitHub pull request'ов в Java/Kotlin + Spring-сервисах.

Оно фиксирует версии кода PR, строит синтаксический индекс, получает структурированный анализ от Codex и связывает его с конкретными строками исходников: sequence-диаграммы вызовов между сервисами, транзакции, SQL, схему БД из миграций, OpenAPI-контракты и тесты. Решение и публикация ревью остаются за вами.

## Возможности

- **Обзор изменений** — описание PR, сценарии и замечания с уровнем риска; каждое утверждение ссылается на файл, версию и строки.
- **Sequence-диаграммы** — вызовы между сервисами и классами, обращения к БД, рамки `@Transactional` и программных транзакций jOOQ.
- **SQL** — восстановленные по коду jOOQ/ORM/JDBC запросы с параметрами и явными неизвестными.
- **База данных** — схема до и после PR по SQL-миграциям (Flyway и др.).
- **Контракты и тесты** — изменения OpenAPI, диаграммы шагов тестов.
- **Код и ревью** — дерево проекта, diff, комментарии к строкам, переход к определению метода, отметки «Просмотрен».
- **Повторное ревью** — после обновления PR анализируется только разница, статусы прежних замечаний и новые ответы.
- **Публикация** — Comment / Request changes / Approve в GitHub от вашего имени, только по кнопке.

Подробно — в [docs/FEATURES.md](docs/FEATURES.md).

## Что происходит с вашим кодом

- **Код отправляется в OpenAI.** Для анализа текст изменённых файлов и связанных исходников выбранных репозиториев передаётся модели через [Codex SDK](https://github.com/openai/codex). Не используйте приложение для кода, который нельзя отправлять внешнему провайдеру.
- **Всё остальное хранится локально** — в каталоге `.review/` (SQLite и снимки кода). Сервер слушает только `127.0.0.1` и отклоняет запросы с чужих доменов.
- **В GitHub ничего не публикуется без вас.** Ревью отправляется только кнопкой «Отправить ревью» после предпросмотра.
- **Codex работает без инструментов.** Shell, сеть и MCP отключены; модель получает код как данные, а не инструкции. `AGENTS.md`/`CLAUDE.md` из репозиториев не загружаются.
- **Секреты отфильтровываются, но не гарантированно.** Из снимков пропускаются `.env*`, ключи, keystore и каталоги секретов. Это не замена проверке репозитория на случайно закоммиченные секреты.
- **Анализируемый код не запускается** — ни сборки, ни тесты, ни миграции, ни SQL.

## Требования

- **Node.js 24 LTS** (или 22.13+) — нужен встроенный `node:sqlite`.
- **Git**.
- **[GitHub CLI](https://cli.github.com/)**, авторизованный через `gh auth login`. Для fine-grained токенов нужны права `Contents: read` и `Pull requests: write`.
- **Доступ к Codex** — вход через [Codex CLI](https://github.com/openai/codex) (`codex login`) или переменная `OPENAI_API_KEY`.
- Для кнопки выбора папки: в macOS и Windows используется системный диалог, в Linux — `zenity`. Путь можно ввести и вручную.

## Быстрый старт

### Попробовать без аккаунтов

Демо создаёт временные Git-репозитории и имитирует GitHub и Codex — ничего не отправляется наружу.

```sh
npm ci
npm run demo
```

Откройте **http://127.0.0.1:4318**.

### Работа с настоящими PR

```sh
npm ci
gh auth login
npm install -g @openai/codex   # если Codex CLI ещё не установлен
codex login --device-auth      # или: export OPENAI_API_KEY=...
npm run build
npm start
```

Откройте **http://127.0.0.1:4318**.

### Режим разработки

```sh
npm run dev
```

Интерфейс с горячей перезагрузкой — **http://127.0.0.1:5173**, API — на порту 4318.

## Как пользоваться

1. **Создайте ревью.** Нажмите «Новое ревью», выберите папку локального Git-репозитория (origin должен быть на `github.com`) и нажмите «Подключить».
2. **Выберите PR** для каждого изменяемого репозитория. Репозитории других сервисов можно подключить как контекст — на их текущем локальном HEAD.
3. **Нажмите «Анализировать».** Прогресс виден в реальном времени, анализ можно отменить. Результаты сохраняются локально.
4. **Изучите результат** во вкладках «Обзор», «Взаимодействия», «Контракты», «База данных», «Тесты».
5. **Оставьте комментарии** во вкладке «Код и ревью»: выделите строки в diff или добавьте замечание модели в черновик.
6. **Опубликуйте ревью**: «Черновик» → выберите Comment / Request changes / Approve → «Проверить и отправить» → «Отправить ревью».

Если PR обновился, нажмите «Проверить обновления»: приложение проанализирует только изменения с прошлого ревью и покажет статусы прежних замечаний.

## Настройки

Переменные окружения сервера:

| Переменная           | По умолчанию                 | Назначение                                                  |
| -------------------- | ---------------------------- | ----------------------------------------------------------- |
| `REVIEW_PORT`        | `4318`                       | Порт локального сервера                                     |
| `REVIEW_DATA_DIR`    | `.review` в рабочем каталоге | База и снимки кода                                          |
| `REVIEW_CODEX_MODEL` | модель SDK по умолчанию      | Модель Codex для анализа                                    |
| `REVIEW_CODEX_BIN`   | CLI из SDK                   | Явный путь к Codex CLI                                      |
| `OPENAI_API_KEY`     | —                            | Альтернатива входу через `codex login`                      |
| `CODEX_HOME`         | `~/.codex`                   | Откуда взять `auth.json`; остальная конфигурация не берётся |

В режиме разработки Vite проксирует `/api` на порт 4318; для другого порта измените proxy в `vite.config.ts`.

## Частые проблемы

- **«GitHub не подключён» в левом нижнем углу** — выполните `gh auth login` и перезапустите сервер.
- **«Нет файловой авторизации Codex»** — выполните `codex login --device-auth` или задайте `OPENAI_API_KEY` перед `npm start`.
- **Порт 4318 занят** — демо и обычный сервер используют один порт; запускайте их по очереди или задайте `REVIEW_PORT`.
- **`ExperimentalWarning: SQLite`** в консоли — ожидаемо, модуль `node:sqlite` пока помечен экспериментальным.

## Ограничения

- Последовательность вызовов и транзакции восстанавливаются статически по коду; реальные пути исполнения без трассировок не подтверждаются.
- Снимок — до 6000 текстовых файлов / 64 МБ на сторону, файл — до 1 МБ. Контекст модели — до 550 тыс. символов, изменения идут первыми; усечение явно отмечается в результате.
- SQL — реконструкция модели с неизвестными частями, а не запрос настоящего ORM.
- Контракты извлекаются только из изменённых OpenAPI JSON/YAML.
- Несколько PR публикуются по отдельности, без общей транзакции.
- `npm audit` показывает 4 moderate-уязвимости в цепочке `swagger-ui-react → remarkable → argparse → sprintf-js`; исправленной версии пока нет. Внешние сетевые запросы Swagger UI заблокированы CSP.

## Разработка

```
server/   Fastify API, анализ, Git, GitHub, индексатор Tree-sitter
shared/   модель данных (Zod-схемы) и логика, общая для сервера и интерфейса
web/      интерфейс на React
tests/    тесты Vitest; настоящие временные Git-репозитории, GitHub и модель подменены
docs/     подробная документация
```

Перед отправкой изменений:

```sh
npm run typecheck
npm test
npm run format:check
npm run build
```

`npm run test:codex` проверяет настоящий Codex SDK на маленьком синтетическом проекте — он расходует лимит модели, но ничего не публикует.

Чтобы подключить другую модель, реализуйте интерфейс `AnalysisProvider` из `server/provider.ts`. HTTP API описан в [docs/FEATURES.md](docs/FEATURES.md#http-api).
